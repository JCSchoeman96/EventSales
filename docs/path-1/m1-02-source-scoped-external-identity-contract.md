## 4. Source Canonicalization Contract

### 4.1 Persisted SourceSystem.base_url (canonical_source_key component)

Implemented by `EventSales.Catalog.Changes.NormalizeBaseUrl`:

```text
String.trim(url)
|> String.trim_trailing("/")
```

Evidence: `lib/event_sales/catalog/changes/normalize_base_url.ex:17-21`.

Applied on SourceSystem `:create` and `:update` (`source_system.ex:30-44`).

| Concern | Current rule |
| --- | --- |
| Trailing slash | Removed |
| Leading/trailing whitespace | Trimmed |
| Empty string | Rejected (`attribute_does_not_equal(:base_url, "")`) |
| Case (scheme/host) | **Preserved as stored** (no downcase) |
| Scheme/host/path URI parse | **Not performed** on persist |
| Query/fragment | Left as stored (not stripped by Ash change) |
| Timing | On create/update change only |

Bootstrap uses the same trim semantics: `lib/event_sales/maintenance/source_system_bootstrap.ex:57`.

`kind` constraints: only `:woocommerce` (`source_system.ex:62-66`).

### 4.2 Producer-hash input normalization (DiscoveryIntegrity)

Implemented by `DiscoveryIntegrity.normalize_base_url/1`:

```text
URI parse
scheme ∈ {http, https}, downcased
host present, downcased
default ports stripped (http:80, https:443)
path trailing slash trimmed; "/" → ""
query and fragment discarded by URI rebuild
```

Evidence: `discovery_integrity.ex:57-77,261-279`; tests `discovery_integrity_test.exs:160-198`.

Examples locked by tests:

```text
HTTPS://Example.com/     → https://example.com
https://example.com:443/ → https://example.com
http://example.com:80/   → http://example.com
https://example.com/Path/?q=1#frag → https://example.com/Path
```

### 4.3 Compatibility decision (D4)

```text
VERIFY BINDING: COMPATIBLE / SAFE

verify_source_system_id(source_system.base_url, wire_id)
always re-applies DiscoveryIntegrity.normalize_base_url/1
before hashing. Case/port variants of a stored base_url still verify
against a producer hash derived from DiscoveryIntegrity normalization.

PERSISTED UNIQUENESS vs HASH INPUT SPACE: NOT IDENTICAL

Ash unique_kind_base_url uses trim-only strings.
DiscoveryIntegrity collapses host/scheme case and default ports.

Therefore two SourceSystem rows could theoretically differ by URL case
yet share one producer_source_system_id.

Classification:
  not M1-02 BLOCKED (meanings remain unambiguous; verify is fail-closed)
  future implementation gap: align NormalizeBaseUrl with DiscoveryIntegrity
  (see §15)
```

This mismatch was not previously named “designed”; it is **safe for current verify binding** and **must not be silently ignored** for multi-source uniqueness.

Do not invent additional URL normalization in this contract beyond the two implementations above.

## 5. Source Identity Resolution / Binding

### Supported direction

```text
canonical_source_key (kind + NormalizeBaseUrl(base_url))
        ↓ Ash create/read
SourceSystem durable row
        ↓
internal_source_pk (SourceSystem.id)

SourceSystem.base_url
        ↓ DiscoveryIntegrity.normalize_base_url
        ↓ sha256 → lowercase hex
producer_source_system_id ("wordpress_tickera:" <> hash)

producer_source_system_id (from wire)
        ↓ verify_source_system_id(SourceSystem.base_url, wire)
same source contract OR fail :source_system_id_mismatch
```

Native discovery path:

```text
configured internal_source_pk
  → load SourceSystem
  → verify producer_source_system_id against SourceSystem.base_url
```

Evidence: `wordpress_feed_discovery_source.ex:66-72,99+`.

### Not supported

```text
Reverse durable lookup:
  producer_source_system_id → SourceSystem row
```

The repository does not store producer IDs as a column and does not index them. Do not invent reverse resolution.

Webhook intake resolves source by “first active Woo SourceSystem” (`webhook_intake.ex:360-368`), not by producer ID or base_url match — see §13.

```text
  unique (source_system_id, woo_product_id, woo_variation_id)
```

```text
  same three columns (aligned)

  (source_system_id, woo_variation_id) alone
```

Parent product ID is part of the Path 1 variation identity contract even when a lookup temporarily filters by variation under a known product.

That is **storage under an event**, not a second global product identity authority. Using TicketType vs ProductMapping for **attribution** is M1-03.

## 9. Lookup Contract

### Global principle

```text
A raw external numeric ID alone must never be sufficient across sources.
```

| Entity | Required source context | Lookup fields | Cardinality | Not found | Duplicate | Conflict |
| --- | --- | --- | --- | --- | --- | --- |
| Event | `internal_source_pk` | + `external_event_kind`, `external_event_id` | 0..1 when external set | treat as unknown identity (fail closed for attribution — M1-03) | DB unique rejects | fail closed |
| Logical product | `internal_source_pk` | + `woo_product_id` (+ active) | 0..1 active product-level | pending/unmapped (M1-03) | active unique rejects | fail closed |
| Logical variation | `internal_source_pk` | + `woo_product_id` + `woo_variation_id` (+ active) | 0..1 active | pending (M1-03) | active unique rejects | fail closed |
| Order | `internal_source_pk` | + `woo_order_id` | 0..1 | create path | unique rejects | fail closed |
| OrderItem | parent `order_id` (inherits source) | + `woo_line_item_id` | 0..1 | create path | unique rejects | fail closed |
| SourceSystem by canonical key | — | `kind` + normalized `base_url` | 0..1 | missing source | unique rejects | fail closed |

### Forbidden examples

```text

```

```text

  — event_id already binds source via Event
```

## 10. Cross-Source Collision Matrix

| Case | Expected behaviour |
| --- | --- |
| Source A Woo order 123 / Source B Woo order 123 | **Legitimate** — distinct Orders under distinct `internal_source_pk` |
| Source A Woo product 123 / Source B Woo product 123 | **Legitimate** — distinct ProductMapping namespaces |
| Source A Tickera event 123 / Source B Tickera event 123 | **Legitimate** — distinct Events under distinct sources |
| Same `kind` + same NormalizeBaseUrl(`base_url`) | **Conflict** — `unique_kind_base_url` rejects |
| Same `base_url` string with different `kind` | Currently only `:woocommerce` exists; if future kinds appear, tuples differ |
| Same DiscoveryIntegrity-normalized URL with different stored case variants | **Verification** may treat as same producer ID; **persisted uniqueness** may allow two rows — documented GAP (§15); operators must not create duplicate case variants |
| `producer_source_system_id` for wrong `base_url` | **Fail closed** — `:source_system_id_mismatch` / discovery `:invalid_feed_response` |
| Malformed producer ID | **Fail closed** — mismatch / invalid |
| Unknown `internal_source_pk` | **Fail closed** — missing SourceSystem |
| External ID valid format but wrong source used in lookup | Must not resolve across sources; returns not-found in correct namespace |

Same numeric IDs under different sources are **first-class legitimate**.

## 11. Historical Identity Immutability

| Identity | Path 1 immutability rule | Current action surface note |
| --- | --- | --- |
| `internal_source_pk` | Immutable | PK |
| `canonical_source_key` components | Treat as identity; changing `base_url`/`kind` redefines the source — must be rare and explicit | `:update` accepts `kind`/`base_url` today |
| Event `(source, kind, external_event_id)` | **Immutable** once set for a durable Tickera-linked event | `:update` still accepts external fields — enforcement gap vs contract |
| ProductMapping Woo product/variation IDs | **Immutable identity** for a mapping row’s external product/variation | `:remap`/`:update` can change IDs — deliberate ops action with PaperTrail; not silent rewrite |

| OrderItem `woo_product_id` / `woo_variation_id` | Historical source line facts — preserve; do not “correct” by collapsing variation→product | Synced from source payloads |

```text
names, titles, labels, slugs, SKUs, current_label, original_label,

```

Names/titles/SKUs/slugs are **never** relationship identity authority (programme invariant).
